## 9. 예상 결과 (실험 완료 전 예상)

**[주의] 이 장과 다음 장의 내용은 모두 실험이 끝나기 전에 쓴 예상이다. 확정된 실험 결과가 아니며, 실험 종료 후 실측값으로 교체한다.** 예상의 근거는 작성 시점(2026-11-16)까지 얻은 중간 측정값과 각 방법의 구조적 특성이다. HGT 와 bge-m3 + LLM 은 아직 측정값이 없어 불확실성이 특히 크다.

### 9.1 예상 지표 (표본 쿼리 599개, 과제 → 기업, 전체 관계 합산)

| 방법 | Hits@10 (예상) | Hits@100 (예상) | NDCG@10 (예상) | 예상 근거 |
|---|---|---|---|---|
| bge-m3 | 0.60 내외 | 0.69 내외 | 0.51 내외 | 후보 생성 직후의 중간 측정값 |
| bge-m3 + LLM | 0.50 ~ 0.65 | 0.69 내외 (bge-m3 와 동일) | 0.40 ~ 0.55 | 미측정. 아래 9.2 의 추론 |
| LightGCN | 0.32 내외 | 0.40 내외 | 0.26 내외 | 학습 완료 후 중간 측정값 |
| LightFM | 0.21 내외 | 0.42 내외 | 0.12 내외 | 학습 완료 후 중간 측정값 |
| HGT | 0.30 ~ 0.50 | 0.45 ~ 0.70 | 0.25 ~ 0.40 | 미측정. LightGCN 과 비슷하거나 높을 것으로 예상 |

Recall@K 는 과제 → 기업 방향에서 쿼리당 정답이 대부분 1개이므로 Hits@K 와 거의 같을 것으로 예상한다. NDCG@100 은 NDCG@10 보다 0.01 ~ 0.04 높은 수준으로 예상한다.

### 9.2 예상되는 경향

1. **(예상) bge-m3 단독이 전체 지표에서 가장 높게 나올 것이다.** 다만 이는 과제설명문에 적힌 수행기관명이 임베딩에 반영된 결과로 보인다(3.5절). 연결 기업명이 없는 쿼리에서는 bge-m3 의 Hits@10 이 0.2 대로 떨어질 것으로 예상한다.
2. **(예상) LLM 재랭킹은 전체 Hits@10 을 높이지 못하거나 오히려 낮출 수 있다.** LLM 프롬프트에서는 연결 기업명을 가리므로, LLM 은 임베딩이 이름으로 찾아낸 정답을 기술 내용만으로 다시 판단해야 한다. 기업명이 있는 쿼리에서는 순위가 내려가고, 기업명이 없는 쿼리에서는 소폭(수 %p) 개선될 것으로 예상한다.
3. **(예상) 과제수행 관계의 지표가 기술이전·사업화보다 높을 것이다.** 수행기관명이 설명문에 직접 적혀 있고, 과제와 수행 기업의 기술 내용이 가장 가깝기 때문이다.
4. **(예상) LightGCN 은 상위 순위(@10)에서, LightFM 은 넓은 범위(@100)에서 상대적으로 강할 것이다.** LightGCN 은 그래프 전파로 연결 이력이 있는 기업을 상위에 올리지만, 이력이 없는 기업(전체의 약 95%)은 구분하기 어렵다. LightFM 은 내용 피처로 전체 기업을 고르게 순위화한다.
5. **(예상) HGT 는 LightGCN 보다 Hits@100 이 높을 것이다.** 비선형 변환과 출력 사영이 있어 간선이 없는 기업도 내용 피처로 구분할 수 있기 때문이다. 다만 30 에폭으로 충분히 수렴하는지는 확인이 필요하다.
6. **(예상) 연결 기업명이 없는 쿼리에서는 방법 간 격차가 크게 줄어들 것이다.** 이 집단에서 그래프 학습 모델이 bge-m3 단독과 비슷하거나 앞설 가능성이 있다.

### 9.3 기업명 제거 재임베딩이 결과에 미치는 영향 (예상)

**[주의] 이 절도 예상이다.** 9.1 의 예상 지표는 기업명이 들어간 설명문으로 만든 bge-m3 벡터 기준이다. 3.6절의 재임베딩(기업명을 제거한 설명문) 이후에는 아래와 같이 달라질 것으로 예상한다.

예상의 근거는 기업명이 들어간 벡터로 측정한 다음 중간 측정값이다 (표본 599쿼리, 전체 관계 합산). LightGCN 값은 학습이 붕괴한 모델의 것이라 참고용이다.

| 모델 | 기업명 있는 쿼리 (364개) Hits@10 / @100 | 기업명 없는 쿼리 (235개) Hits@10 / @100 |
|---|---|---|
| bge-m3 단독 | 0.849 / 0.918 | 0.226 / 0.332 |
| LightFM | 0.302 / 0.558 | 0.072 / 0.209 |
| LightGCN | 0.360 / 0.442 | 0.247 / 0.323 |

**예상과 실측의 비교 (bge-m3 단독).** 이 절을 쓴 뒤 재임베딩이 끝나 bge-m3 단독은 실측값을 얻었다 (3.7절). 전체 Hits@10 은 0.117, Hits@100 은 0.264 로, 아래 표의 예상(0.25 ~ 0.35, 0.40 내외)보다 낮았다. 쿼리 집단 간 격차가 사라진다는 예상과 과제수행 관계의 하락이 가장 크다는 예상은 맞았다. 나머지 모델의 예상은 이 실측을 반영하지 않은 원래 예상 그대로이며, bge-m3 벡터에 의존하는 모델일수록 아래 예상보다 낮게 나올 가능성이 있다.

**예상과 실측의 비교 (LightFM, LightGCN).** 이후 얻은 중간 실측(7.2절)에서 LightFM 은 Hits@10 0.058, Hits@100 0.255 로, 아래 표의 예상(0.08 ~ 0.15, 0.25 ~ 0.35)보다 @10 이 낮았다. LightGCN 은 Hits@10 0.058 로 예상(0.25 ~ 0.35)보다 크게 낮았다. "그래프 학습 모델이 임베딩 단독과 비슷하거나 앞설 가능성"이라는 예상은 지금까지의 결과와 맞지 않는다. 다만 GNN 학습 방식을 고치는 중(5.6절)이라 최종 결과는 달라질 수 있다.

**예상과 실측의 비교 (과제 → 기업 전체 결과, 7.2절).** bge-m3 + LLM 은 Hits@10 0.197 로 bge-m3 단독(0.117)보다 높았다. "재임베딩 후 LLM 재랭킹 효과가 드러난다"는 예상과 맞는다. LightGCN 은 학습 방식을 고친 뒤 Hits@100 0.361 로 bge-m3 단독(0.264)을 넘었다. "그래프 학습 모델이 임베딩 단독과 비슷하거나 앞설 가능성"은 Hits@100 에서는 맞았고 Hits@10 에서는 비슷한 수준이다. HGT 에 대한 "LightGCN 보다 Hits@100 이 높을 것"이라는 예상(9.2절 5번)은 40 에폭 시점까지는 맞지 않는다.

**예상과 실측의 비교 (확장 그래프, 기업 → 과제, 재랭킹 깊이; 7.4 ~ 7.6절).** 그래프 확장(3.8절)이 간선 없는 노드에 대한 LightGCN 의 약점을 줄일 것이라는 기대는 맞지 않았다. 과제 → 기업은 확장 전후가 같았고(Hits@100 0.361 → 0.354), 기업 → 과제는 0.024 에서 0.046 으로 오르는 데 그쳤다. 기업 → 과제에서도 LLM 재랭킹은 bge-m3 단독의 Hits@10 을 0.125 에서 0.184 로 올려, 과제 → 기업과 같은 효과를 보였다. 재랭킹 깊이를 500 까지 넓히면 bge-m3 + LLM 의 Hits@100 이 0.394(과제 → 기업), 0.399(기업 → 과제)로 올라, "후보 검색 단계의 품질이 상한을 정한다"는 예상 결론(10장 3번)과 맞는다. HGT 는 확장 그래프에서 전체 그래프 학습이 메모리에 들어가지 않아 미니배치 학습으로 바꿨으며 결과는 아직 없다.

재임베딩 후 예상 지표 (표본 쿼리, 전체 관계 합산):

| 방법 | Hits@10 (예상) | Hits@100 (예상) | 예상 변화와 이유 |
|---|---|---|---|
| bge-m3 단독 | 0.25 ~ 0.35 | 0.40 내외 | 크게 하락. 기업명 있는 쿼리의 성능이 기업명 없는 쿼리 수준으로 내려간다. 수행 기업은 기술 내용도 가까워 그보다는 조금 높을 수 있다 |
| bge-m3 + LLM | bge-m3 단독보다 높음 | bge-m3 단독과 동일 | 정답이 후보 100개 안의 중간 순위에 있는 경우가 늘어 LLM 재랭킹 효과가 드러날 여지가 생긴다. 다만 후보 안에 정답이 들어오는 비율이 줄어 상한이 낮아진다 |
| LightFM | 0.08 ~ 0.15 | 0.25 ~ 0.35 | 가장 크게 하락. 그래프 전파 없이 bge-m3 벡터의 변환만 쓰며, 현재 성능이 기업명 있는 쿼리에 몰려 있다 |
| LightGCN | 0.25 ~ 0.35 | 미정 | 상대적으로 덜 하락. 연결 이력을 전파하는 신호는 임베딩과 무관하다. 학습 방식도 함께 바뀌어 불확실성이 크다 |
| HGT | 미정 | 미정 | 정상 학습된 결과가 아직 없다. 내용 피처 의존도가 LightGCN 보다 높아 영향은 LightGCN 과 LightFM 의 중간으로 예상한다 |

예상되는 전체 경향:

1. **(예상) 모든 모델의 절대 수치가 내려간다.** 내려간 수치가 기술 내용 기반 매칭 능력에 더 가깝다.
2. **(예상) 모델 간 순위가 바뀔 수 있다.** 재임베딩 전에는 bge-m3 단독이 가장 높지만, 재임베딩 후에는 그래프 학습 모델이 임베딩 단독과 비슷하거나 앞설 가능성이 있다.
3. **(예상) 관계별로는 과제수행의 하락이 가장 크다.** 설명문에 이름이 적힌 기관이 수행 기업이기 때문이다. 기술이전과 사업화는 상대가 수행 기업과 같은 경우에만 영향을 받는다.
4. **(예상) 기업명 있는 쿼리와 없는 쿼리의 지표 격차가 크게 줄어든다.** 격차가 여전히 크면 이름 제거가 불완전하다는 뜻이므로, 이 격차를 재실험의 점검 항목으로 쓴다.
5. **(예상) 유사도 간선을 쓰는 GNN 학습에서는 과제와 수행 기업을 바로 잇던 간선이 줄어든다.** 유사도 간선이 이름이 아니라 내용 유사도로 만들어지기 때문이다.

## 10. 예상 결론 (실험 완료 전 예상)

**[주의] 아래 결론은 예상이며, 실측 결과에 따라 바뀔 수 있다.**

1. **(예상)** 현재 데이터에서는 설명문에 포함된 기업명이 가장 강한 매칭 신호로 작용해, 임베딩 유사도만으로도 held-out 연결의 상당수를 찾는다. 이 수치를 기술 매칭 성능으로 해석해서는 안 된다.
2. **(예상)** 관계 그래프를 학습한 모델(LightGCN, HGT, LightFM)은 기업명 신호를 제외하면 임베딩 단독과 비슷하거나 나은 성능을 보일 것이다. 다만 연결 이력이 있는 기업이 전체의 5% 에 불과해, 그래프 신호만으로는 한계가 있다.
3. **(예상)** LLM 재랭킹의 가치는 기업명에 기대지 않는 내용 기반 판단에 있으며, 그 효과는 기업명이 없는 쿼리의 @10 지표에서 확인될 것이다. 후보 100개 안에 정답이 없으면 LLM 이 개선할 수 없으므로, 후보 검색 단계의 품질이 상한을 정한다.
4. **(예상)** 따라서 실용적인 구성은 그래프 학습 모델 또는 임베딩으로 후보를 넓게 검색하고 LLM 으로 재랭킹하는 2단계 방식일 것이다. 이를 확인하려면 LightGCN + LLM, HGT + LLM, LightFM + LLM 의 추가 실험이 필요하다.

### 10.1 후속 과제 (예상 결과와 무관하게 필요한 작업)

- 기업명을 제거한 설명문으로 만든 bge-m3 벡터(3.6절)로 전체 실험을 반복하고, 9.3 의 예상과 비교한다 (HGT 를 제외하고 완료).
- 각 검색 모델의 후보를 LLM 으로 재랭킹하는 실험(LightGCN + LLM, HGT + LLM, LightFM + LLM)을 수행한다.
- 쿼리 표본을 늘려 모델 간 차이의 통계적 유의성을 확인한다.
- 기업 → 과제 방향 평가는 추가했다(7.5절). 하이퍼파라미터 탐색은 남아 있다.
- LightGCN 후보와 bge-m3 후보를 합쳐 LLM 으로 재랭킹하는 구성을 확인한다. 두 모델이 서로 다른 정답을 찾으므로(6.4절) 후보 포함률이 오를 것으로 예상한다.
